# TEST_PLAN — 테스트 계획

## 1. 원칙

1. **삭제/제거 테스트는 가짜 환경에서만.** 실제 시스템 경로(`C:\Windows`, `C:\Users` 등)나 실제 설치 프로그램에 삭제/제거를 실행하지 않는다 (SAFETY.md §11).
2. **실패해야 하는 테스트(거부 테스트)가 성공 테스트만큼 중요하다.**
3. 안전 모듈(`src/main/safety`)과 규칙 검증기는 **라인/분기 커버리지 90% 이상**을 목표로 한다.
4. 테스트는 Windows에서 실행되는 것을 전제로 하되, 순수 로직(경로 정규화/매칭)은 OS 비의존으로 짠다.
5. 테스트에서 안전 검사를 끄는 플래그를 프로덕션 코드에 두지 않는다. 허용 루트를 **주입**한다.

## 2. 도구

| 종류             | 도구                  | 위치              |
| ---------------- | --------------------- | ----------------- |
| 단위/통합        | Vitest                | `tests/unit/`     |
| E2E              | Playwright (Electron) | `tests/e2e/`      |
| 가짜 파일 시스템 | fixtures 생성기       | `tests/fixtures/` |

## 3. fixtures 생성기 (`tests/fixtures/`)

`createFixtureTree(options)` → `os.tmpdir()` 아래 **고유 임시 폴더**(`disklens-test-<random>`)를 만들고 정해진 구조를 생성, `cleanup()`으로 테스트 종료 시 제거.

구성 옵션/내용:

- 알려진 크기의 파일들 (예: 1KB, 1MB, 10MB; 합계가 정확히 계산되도록).
- 깊은 중첩(깊이 50+), 많은 작은 파일(수천 개), 빈 폴더.
- 가짜 `Temp`, `Cache`, `node_modules`, `Library` 폴더 (규칙 매칭 테스트용 경로 패턴을 흉내).
- 심볼릭 링크/정션: 폴더 링크가 순환하는 경우 포함 (생성 불가 시 테스트 skip 처리, 이유 출력).
- 읽기 권한 없음 흉내(가능한 범위에서; 불가하면 모킹).
- "보호 폴더 흉내": `Windows`, `Program Files`, `Users\<name>\Documents` 이름의 폴더를 **임시 루트 안에** 만들고, 테스트용 보호 경로 목록을 주입해서 "이 임시 폴더 안의 `Windows`는 보호 경로"로 취급.
- 가짜 설치 프로그램 레지스트리 데이터: 파일(JSON)로 만든 모의 레지스트리 어댑터.
- 모의 제거 프로그램: 종료 코드 0/1/지연/존재하지 않음을 흉내내는 작은 스크립트(node 스크립트 또는 cmd) — 인자를 기록 파일에 남겨 실행 여부를 검증.

## 4. 단위 테스트 항목

### 4.1 스캔 엔진 (2단계)

- [ ] 폴더 크기 합 = 파일 크기 합 (정확한 값 검증)
- [ ] 직계 파일 합(`ownFilesSize`)과 하위 합 구분
- [ ] 링크/정션을 따라가지 않음, 순환 링크에서 무한 루프 없음, 이중 집계 없음
- [ ] 권한/존재하지 않음 오류 → 건너뜀 집계(크래시 없음)
- [ ] 취소: 1초 내 중단, 부분 결과 처리
- [ ] 작은 폴더 접기: 합계 보존(접힌 합 + 표시 합 = 부모 합), 규칙 대상 폴더는 접지 않음
- [ ] Top-K 파일: 정확한 상위 K개, 정렬
- [ ] 유형별 집계 합 = 전체 파일 합
- [ ] 디스크 점유 크기(클러스터 올림) 계산
- [ ] 결과 캐시 저장→로드 왕복 동일
- [ ] 진행 이벤트가 스로틀 간격을 지킴

### 4.2 규칙 DB (4단계)

- [ ] 스키마 검증 실패 시 해당 규칙 거부 + 나머지는 로드
- [ ] DATA_SPEC §1.2 검증 규칙 8개 각각의 위반 케이스가 거부됨
  1. cleanable + protected
  2. cleanable인데 cleanup 없음
  3. allowPermanent인데 카테고리 부적합
  4. defaultSelected인데 safe 아님
  5. 보호 경로 침범 / 정리 허용 예외 밖
  6. 지나치게 넓은 패턴(`C:\`, `C:\Users`, 개인 폴더 루트)
  7. id 중복
  8. 사용자 규칙이 protected를 낮추려 함
- [ ] 환경변수 확장(`%LOCALAPPDATA%` 등) 정확, 미정의 변수 처리
- [ ] 매처: exact > 긴 prefix/glob > name 우선, 동률 시 보수적 안전도
- [ ] 경계: `...\Temp`가 `...\Temp2`를 매칭하지 않음
- [ ] 대소문자 무시, 슬래시/역슬래시 혼용 처리
- [ ] glob(`**`, `*`) 동작
- [ ] 시드 `cleanup-rules.json` 전체가 검증기를 **오류 없이 통과** (CI에서 항상 실행)

### 4.3 프로그램 목록 (5단계)

- [ ] 모의 레지스트리 데이터 파싱: 정상/값 누락/숫자 문자열/날짜 형식 이상
- [ ] 같은 프로그램이 여러 hive에 중복될 때 처리
- [ ] SystemComponent 판별, 숨김 토글
- [ ] ProgramRule 매칭(이름/게시자), 우선순위
- [ ] 설치 폴더 ↔ 스캔 노드 연결(경계 포함)

### 4.4 안전 모듈 — **삭제 안전 테스트** (6단계, 최우선)

거부되어야 하는 케이스 (모두 `canDelete === false` + 이유 코드):

- [ ] 보호 경로 그 자체 (`Windows`, `Program Files`, 드라이브 루트, 사용자 루트, `Documents` 등)
- [ ] 보호 경로의 하위(`Windows\System32\x.dll`)
- [ ] 허용 예외가 아닌 보호 하위
- [ ] `..` 우회: `<허용루트>\..\Windows`
- [ ] 슬래시 혼용/대소문자 변형/`\\?\` 접두사/8.3 짧은 이름 변형
- [ ] **정션/심볼릭 링크 우회**: 허용 루트 안의 링크가 보호 경로를 가리킴 → 거부
- [ ] 접두사 경계: 허용 루트 `...\Temp`, 대상 `...\Temp2\x` → 거부
- [ ] `unknown` 대상(규칙 없음), `protected` 규칙 대상
- [ ] `caution` + `acknowledgeCaution` 없음
- [ ] 영구 삭제 요청인데 규칙 `allowPermanent=false`, 또는 설정에서 비허용
- [ ] 확인 토큰 없음/이미 사용/만료/다른 계획의 토큰/계획 내용 변경 후 토큰
- [ ] 계획(plan) 이후 대상이 보호 경로로 바뀐 경우(실행 직전 재검사)
- [ ] 폴더 자체 삭제(`mode: self`)가 규칙에 없는 폴더에 요청됨
- [ ] 경로 인자가 빈 문자열/널 문자/너무 긴 경로

허용되어야 하는 케이스:

- [ ] 허용 루트 안의 `safe` 규칙 대상(`contents` 모드)이 삭제됨 (폴더는 남고 내용만 삭제)
- [ ] `minAgeDays` 필터 동작(오래된 파일만)
- [ ] `includeGlobs`/`excludeGlobs` 동작
- [ ] `caution` + ack → 허용
- [ ] 휴지통 모드: **trash API는 모킹**하고 호출 인자 검증 (테스트에서 실제 휴지통을 쓰지 않아도 됨, 필요 시 임시 폴더 파일만 사용)

실행 동작:

- [ ] 사용 중 파일(EBUSY) 건너뜀 + 집계, 나머지 계속
- [ ] 취소 시 중단 + 이미 삭제한 것 기록
- [ ] 로그(JSONL)에 거부 건도 기록됨
- [ ] 휴지통 실패 시 **자동으로 영구 삭제로 전환되지 않음**
- [ ] 정리 기록 저장

### 4.5 관리자 헬퍼 (8단계)

- [x] job 파일에 규칙 밖 항목 ID → 거부 (`tests/unit/adminHelper.test.ts`, E2E `helper.spec.ts`)
- [x] job 파일에 임의 경로 필드 → 거부 (strict 스키마, `extra-fields`)
- [x] 변조된 확인 토큰 해시/서명/모드/항목 → 거부 (`bad-token`, `bad-signature`)
- [x] 헬퍼가 safety 검사를 자체 수행 (보호 파일 이름, 링크 건너뜀, 규칙 범위, 영구 삭제 설정을 헬퍼가 다시 판정)
- [x] UAC 거부 시(모의) 항목 `admin-declined`, 앱은 정상, 일반 항목은 그대로 정리

### 4.6 프로그램 제거 (9단계)

- [x] 모의 제거 프로그램 성공/실패/지연/존재하지 않음 (`uninstallService.test.ts`, `e2e/uninstall.spec.ts`)
- [x] UninstallString 파싱: 따옴표 경로, 공백 경로, 인자 포함, `msiexec /x {GUID}` 형식 (`uninstallCommand.test.ts`)
- [x] 인자 주입 시도(`&`, `|`, `;`, 백틱 등) → 셸 미사용 + 문자 자체 거부
- [x] 실행 파일이 없으면 거부
- [x] protected 프로그램 제거 요청 거부 (계획·실행 모두)

### 4.7 IPC 입력 검증

- [ ] 잘못된 타입/누락 필드 → `INVALID_REQUEST`
- [ ] 경로 대신 ID를 받는 채널에 경로 문자열 전달 → 거부
- [ ] 존재하지 않는 ID → `NOT_FOUND`

## 5. E2E 테스트 (Playwright + Electron, 6~11단계)

모든 E2E는 **fixtures 임시 폴더를 스캔 루트로 지정**하고 실행한다 (기본 `C:\` 사용 금지).

- [ ] 앱 기동, 창 표시, 사이드바 이동
- [ ] fixtures 스캔 시작→진행 표시→완료→트리 탐색(펼치기)→취소 동작
- [ ] 앱 재시작 후 캐시된 결과 표시
- [ ] 안전도 배지/설명이 fixtures의 가짜 규칙과 일치하게 표시
- [ ] `protected`/`unknown` 행에 삭제 버튼 없음
- [x] 정리 화면: 분석→선택→확인 대화상자(기본 포커스 취소)→실행→결과(임시 폴더에서만)
- [x] 영구 삭제 옵션: 설정 꺼짐이면 선택 불가, 켜짐이면 체크박스 확인 필요
- [x] 프로그램 화면: 모의 레지스트리 어댑터로 목록 표시, 모의 제거 실행 (`uninstall.spec.ts`)
- [x] 설정(테마·단위·영구 삭제 유지)과 기록 화면 (`settings.spec.ts`), 라이트/다크 대비 (`theme.spec.ts`)
- [x] 설치본(패키징) 점검 (`packaged.spec.ts`, `DISKLENS_PACKAGED_EXE` 가 있을 때만 실행): 규칙 DB 로딩, 스캔 워커, 헬퍼 모드 거부
- [x] 큰 결과 성능 점검 (`perf.spec.ts`, `DISKLENS_PERF_CACHE` 가 있을 때만 실행)
- [ ] 보안 설정: renderer에서 `require`/`process` 접근 불가, 외부 URL 이동 차단

## 6. 성능/부하 테스트 (수동 + 스크립트)

| 항목                 | 방법                      | 기준                                   |
| -------------------- | ------------------------- | -------------------------------------- |
| 실제 `C:\` 스캔 시간 | `npm run scan:cli -- C:\` | 수 분 내 (목표 5분 이내, 실제 값 보고) |
| 스캔 중 메모리       | 프로세스 메모리 측정      | 1.5GB 이하                             |
| 대형 트리 UI         | 수만 행 트리 스크롤       | 끊김 없음                              |
| 취소 반응            | 스캔 중 취소              | 1초 이내                               |
| 생성 fixtures 대량   | 10만 파일 트리            | 정확성 유지                            |

## 7. 수동 검증 체크리스트 (사용자가 직접, 실제 PC)

개발 중 Claude Code가 하지 않고 **사용자가** 수행:

1. 스캔한 폴더 용량을 탐색기 속성 값과 몇 개 대조.
2. 안전(🟢) 항목 중 작은 것(예: 사용자 임시 폴더) 하나를 정리해 보고 용량 변화/휴지통 확인.
3. 관리자 권한 항목 정리 시 UAC 창이 뜨는지, 거부 시 앱이 정상인지.
4. 작은 프로그램 하나를 앱에서 제거해 보기(중요하지 않은 프로그램).
5. 설치 파일로 설치/제거 확인.
6. 정리 후 브라우저/게임/개발 도구가 정상 동작하는지 확인.

## 8. CI/로컬 실행 순서

```bash
npm run typecheck
npm run lint
npm test            # 단위 + 통합 (규칙 시드 검증 포함)
npm run test:e2e    # E2E (fixtures 루트만)
```

- 실패 테스트가 있으면 단계 완료로 보고하지 않는다.
- 새 삭제 경로/규칙 추가 시 해당 거부 테스트도 함께 추가한다.

## 9. 회귀 방지 규칙

- 버그를 수정하면 그 버그를 재현하는 테스트를 먼저 추가한다.
- 규칙 DB를 수정하면 시드 검증 테스트가 CI에서 자동 실행되어야 한다.
- 보호 경로 목록을 변경하는 PR은 테스트에서 "변경 전 목록의 모든 항목이 여전히 보호됨"을 확인하는 스냅샷 테스트를 갱신해야 하며, 목록을 **줄이는** 변경은 사용자 승인을 받는다.
