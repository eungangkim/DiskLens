# ROADMAP — 개발 단계 계획

원칙: **한 번에 한 단계.** 각 단계가 끝나면 (1) typecheck/lint/test 통과 (2) 완료 기준 확인 (3) 사용자에게 쉬운 말로 결과 보고 (4) 다음 단계 진행 여부 확인.
삭제 **UI와 실제 시스템 연결**은 7단계 이전에는 만들지 않는다. 6단계에서는 삭제 엔진을 모듈과 fixtures 테스트로만 만든다(UI 연결 없음). 그 전까지 앱은 "읽기 전용 분석 도구"다.

각 단계에는 **Claude Code에게 줄 지시문 예시**가 있다. 사용자는 그대로 붙여넣으면 된다.

---

## 0단계: 문서 배치 (사용자 작업)

1. 프로젝트 폴더 생성 (예: `disklens`).
2. 루트에 `CLAUDE.md`, `docs/` 폴더에 `PRD.md`, `SAFETY.md`, `ARCHITECTURE.md`, `DATA_SPEC.md`, `UI_SPEC.md`, `ROADMAP.md`, `TEST_PLAN.md` 배치.
3. `resources/` 폴더에 `cleanup-rules.json` 배치.
4. 해당 폴더에서 Claude Code 실행.

**지시문**

> CLAUDE.md와 docs 폴더의 모든 문서를 읽고, 이해한 내용을 10줄 이내로 요약해줘. 모호하거나 충돌하는 부분이 있으면 질문 목록으로 정리해줘. 아직 코드는 작성하지 마.

---

## 1단계: 프로젝트 초기 세팅

**작업**

- Electron + React + TypeScript + Vite(electron-vite) 프로젝트 생성, npm 스크립트(CLAUDE.md §7) 구성.
- main/preload/renderer/shared 폴더 구조(CLAUDE.md §4).
- BrowserWindow 보안 설정(ARCHITECTURE.md §3), CSP, 단일 인스턴스.
- ESLint, Prettier, TypeScript strict, Vitest 설정.
- 빈 화면에 사이드바 5개 메뉴와 상단바 골격만.
- IPC 타입 정의 파일(`src/shared/ipc.ts`)과 preload `window.api` 스켈레톤, "ping" 채널로 왕복 확인.

**완료 기준**

- `npm run dev`로 창이 뜨고 사이드바 메뉴 이동 가능.
- `npm run typecheck`, `lint`, `test` 통과(샘플 테스트 1개).
- renderer에서 Node API 접근이 막혀 있음을 확인(콘솔에서 `require` 불가).
- 보안 설정 3종(contextIsolation/nodeIntegration/sandbox) 확인.

**지시문**

> ROADMAP 1단계를 진행해줘. CLAUDE.md와 ARCHITECTURE.md를 지켜서 초기 세팅만 하고, 기능은 만들지 마. 끝나면 완료 기준을 하나씩 확인한 결과를 보고해줘.

---

## 2단계: 용량 스캔 엔진 (UI 없이 먼저)

**작업**

- `ScanEngine` 인터페이스 + Node 구현(worker_threads). ARCHITECTURE.md §5 준수: 반복 DFS, 링크 미추적, 에러 건너뜀 집계, 폴더 단위 집계 + Top-K 파일 + 유형별 요약 + 작은 폴더 접기.
- 취소, 진행 이벤트(스로틀).
- 스캔 결과 캐시 저장/로드.
- `tests/fixtures`: 가짜 디렉터리 트리 생성기(깊은 중첩, 많은 작은 파일, 심볼릭 링크/정션, 권한 없는 폴더 흉내).
- CLI 스크립트(`npm run scan:cli -- <path>`)로 폴더를 스캔하고 요약을 출력해 성능 측정.

**완료 기준**

- fixtures 트리에 대해 폴더 용량 합이 정확(단위 테스트).
- 정션/링크 이중 집계 없음, 취소 1초 내 중단.
- 실제 `C:\` 스캔 시간/메모리 측정 결과 보고 (목표: 수 분, 메모리 1.5GB 이하). 사용자에게 측정값을 알려주고, 부족하면 병렬 worker 풀 도입 여부 논의.

**지시문**

> ROADMAP 2단계를 진행해줘. UI는 만들지 말고 스캔 엔진, 캐시, CLI, 테스트까지만. 마지막에 내 PC의 C드라이브를 스캔해서 걸린 시간과 최대 메모리 사용량을 알려줘. 이때 파일 삭제 관련 코드는 절대 작성하지 마.

---

## 3단계: 스캔 화면 UI

**작업**

- IPC 연결: `scan:start/cancel/progress/done/getChildren/getTop/getTypeSummary/getSkipped/loadCache`.
- 스캔 화면(UI_SPEC §3): 진행 패널, 폴더 트리(지연 로딩 + 가상 스크롤), 큰 파일/큰 폴더 Top, 유형별 요약, 건너뜀 목록 모달, 상단바 드라이브 용량 막대.
- 탐색기에서 열기, 경로 복사.
- 앱 시작 시 캐시 자동 로드.
- 안전도 컬럼/상세 패널 자리는 만들되 아직 "알 수 없음"으로 표시(규칙은 4단계).

**완료 기준**

- UI에서 스캔 시작/취소/완료 후 트리 탐색 가능, 스캔 중 UI 멈춤 없음.
- 수만 행 스크롤 부드러움.
- 앱 재시작 시 마지막 스캔 결과가 즉시 표시.

**지시문**

> ROADMAP 3단계를 진행해줘. UI_SPEC.md의 스캔 화면을 구현하고, 실제로 앱을 띄워서 스캔→트리 탐색→취소→재시작 후 캐시 표시를 확인해줘. 삭제 버튼은 만들지 마.

---

## 4단계: 규칙 DB + 용도 설명 + 안전도 표시 (읽기 전용)

**작업**

- 규칙 로더: zod 검증, `validate.ts`(DATA_SPEC §1.2 검증 규칙 8개), 환경변수 확장, 정규화, 인덱싱, 매처(우선순위 규칙).
- `resources/cleanup-rules.json` 로드, 사용자 규칙 파일 로드(P1) — 단 protected 낮출 수 없음.
- `rules:describe` 연결, 트리 행에 안전도 배지·설명 표시, 상세 패널(UI_SPEC §3.4), 안전도 필터, "지워도 되는 것만 큰 순" 토글.
- 프로그램 힌트(설치 폴더 연결)는 5단계 완료 후 연결해도 됨.
- 규칙 검증 단위 테스트와 매처 테스트(구체성/동률/경계).

**완료 기준**

- 시드 규칙의 대표 경로가 올바르게 설명/안전도로 표시된다.
- 잘못된 규칙(예: protected인데 cleanable)이 로드 거부된다(테스트).
- `unknown`/`protected` 상세 패널에 삭제 버튼이 없다.
- 실제 내 PC 스캔 결과에서 `unknown` 비율과 큰 `unknown` 폴더 상위 20개 목록을 사용자에게 보고(규칙 보강용).

**지시문**

> ROADMAP 4단계를 진행해줘. DATA_SPEC.md의 검증 규칙을 모두 테스트로 만들고, 스캔 결과에서 규칙에 안 걸린 큰 폴더 상위 20개를 알려줘. 아직 삭제 기능은 만들지 마.

---

## 5단계: 설치 프로그램 목록 (읽기 전용) + 프로그램 규칙

**작업**

- 레지스트리 읽기(Uninstall 3개 위치), 파싱(날짜/용량 예외 처리), 중복 제거, 시스템 컴포넌트 판별.
- 프로그램 규칙 매처(ProgramRule).
- 프로그램 화면(UI_SPEC §5.1~5.2): 목록, 정렬/검색, 시스템 구성요소 토글, 상세. **제거 버튼은 아직 비활성/미구현.**
- 설치 폴더 ↔ 스캔 노드 연결(프로그램 힌트), 스캔 탭 상세 패널의 "프로그램 탭에서 보기".
- 레지스트리 읽기는 **읽기 전용**임을 코드 구조로 보장(쓰기 함수 자체를 만들지 않는다).

**완료 기준**

- Windows 설정의 앱 목록과 대조해 큰 차이 없음(사용자 확인).
- 레지스트리 값 누락/이상 형식에도 크래시 없음(단위 테스트).

**지시문**

> ROADMAP 5단계를 진행해줘. 레지스트리는 읽기만 하고, 제거 기능은 만들지 마. 끝나면 내 PC에서 인식된 프로그램 수와 큰 프로그램 상위 10개를 보여줘.

---

## 6단계: 안전 모듈 + 정리 엔진 (UI 없이, fixtures에서만)

**작업**

- `src/main/safety/`: 보호 경로 하드코딩, 정규화/realpath/접두사 경계, `canDelete` 판정 함수(SAFETY.md §3, §4). **의존성 주입으로 허용 루트 지정 가능**(테스트용).
- 정리 서비스: `plan`(미리보기), `execute`(trash/permanent), 취소, 진행, 확인 토큰(일회용·TTL·계획 바인딩), 로그(JSONL), 정리 기록.
- 규칙 `cleanup` 설정 해석: `contents`/`self`, include/exclude, `minAgeDays`, 사용 중 파일 건너뜀.
- specialAction: 휴지통 비우기(시스템 API), 디스크 정리 호출 — 이 단계에서는 인터페이스만 만들고 실제 호출은 모의(mock) 처리.
- **테스트**: TEST_PLAN.md의 "삭제 안전 테스트" 전부. 모든 삭제 테스트는 fixtures 임시 폴더에서만.

**완료 기준**

- SAFETY.md §12 체크리스트 중 해당 항목 전부 테스트로 증명.
- 보호 경로/`..` 우회/정션 우회/접두사 경계/`unknown`/`protected`/토큰 없음/만료 토큰 거부 테스트 통과.
- 실제 시스템 경로에 대한 삭제 호출이 코드·테스트 어디에도 없음(사용자에게 확인 방법 설명).

**지시문**

> ROADMAP 6단계를 진행해줘. SAFETY.md를 먼저 정독하고, 삭제 로직은 UI 연결 없이 모듈과 테스트로만 만들어. 모든 테스트는 임시 폴더 안에서만 실행되게 해. 끝나면 어떤 공격/실수 시나리오를 막는지 표로 정리해줘.

## 7단계: 정리 화면 UI

**작업**

- 정리 화면(UI_SPEC §4): 그룹별 리스트, 분석, 선택, 안전 항목만 선택, 확인 대화상자(SAFETY §9), 실행/취소/결과 화면, 정리 기록 저장.
- 스캔 상세 패널의 "이 항목 정리하기" 연결(cleanable 항목만).
- 원클릭 안전 정리.
- 관리자 필요 항목 처리: **우선 "관리자 권한 필요" 표시 + 일반 권한에서는 건너뜀**으로 동작하게 하고, 헬퍼는 8단계.
- 영구 삭제 옵션(설정에서 허용 시): UI_SPEC §2.3 경고 흐름.

**완료 기준**

- 임시 폴더 같은 안전 항목 하나를 실제로 정리해 보고(사용자 PC에서 사용자가 직접 실행) 용량 변화 확인.
- `protected`/`unknown`에 삭제 UI 없음.
- 확인 대화상자 기본 포커스 = 취소, 영구 삭제 체크박스 확인.
- 정리 후 결과/기록/로그 파일이 남는다.

**지시문**

> ROADMAP 7단계를 진행해줘. UI_SPEC.md의 정리 화면과 확인 대화상자를 구현해줘. 실제 내 PC에서의 정리 테스트는 내가 직접 할 테니, 너는 fixtures 기반 E2E 테스트까지만 실행해.

---

## 8단계: 관리자 헬퍼 (권한 상승 정리)

**작업**

- `--cleanup-helper` 모드, UAC 상승 실행, job 파일(항목 ID + 확인 토큰 해시 + 모드만), 헬퍼 내 재검증, 결과 반환.
- 거부/실패 처리(`admin-declined`), 관리자 필요 항목(`C:\Windows\Temp`, `SoftwareDistribution\Download` 등) 연결.
- 헬퍼가 임의 경로를 받지 않음을 테스트(변조된 job 파일 거부).

**완료 기준**

- UAC 거부 시 앱이 정상이고 해당 항목만 건너뜀.
- 변조된 job(규칙 밖 항목 ID, 경로 직접 지정)이 거부된다.

**지시문**

> ROADMAP 8단계를 진행해줘. 관리자 헬퍼는 임의 경로를 받지 말고 규칙 ID만 받게 해. 변조된 job 파일이 거부되는 테스트를 꼭 포함해줘.

---

## 9단계: 프로그램 제거

**작업**

- `UninstallString`/`QuietUninstallString` 안전 파싱(셸 미사용, 실행 파일 존재 확인), 실행, 종료 대기, 종료 코드 처리.
- 제거 확인 대화상자, 목록 새로고침, 남은 폴더 후보 알림(P1).
- 프로그램 규칙의 `protected`는 버튼 비활성, `caution`은 경고.
- 테스트는 **모의 제거 프로그램**(fixtures가 만드는 더미 exe/스크립트)로만.

**완료 기준**

- 모의 제거 프로그램 실행/완료/실패 시나리오 테스트 통과.
- 이상한 UninstallString(공백/따옴표/인자 주입)에 안전.
- 실제 PC에서 사용자가 작은 프로그램 하나로 직접 시험.

**지시문**

> ROADMAP 9단계를 진행해줘. 제거 테스트는 모의 제거 프로그램으로만 하고, 실제 설치된 프로그램을 제거하는 코드를 개발 중에 실행하지 마.

---

## 10단계: 설정, 기록, 다듬기

**작업**

- 설정 화면(UI_SPEC §7), 기록 화면(§6), 사용자 규칙 불러오기, 테마, 단위, 제외 폴더.
- 오류 처리/빈 상태/토스트 정리, 접근성(키보드/포커스), 다크 모드 점검.
- 성능 점검(큰 스캔 결과에서 트리/Top 목록), 메모리 점검.
- 규칙 DB 보강(4단계 보고서의 `unknown` 큰 폴더 기준).

**완료 기준**

- UI_SPEC §10 체크리스트 전부 충족.
- PRD의 P0/P1 기능 완료 조건 점검표 작성(통과/미통과).

**지시문**

> ROADMAP 10단계를 진행해줘. PRD.md의 모든 기능에 대해 완료 조건 점검표를 만들어서 통과/미통과를 정직하게 표시해줘.

## 11단계: 배포 (설치 파일)

**작업**

- `electron-builder.yml`: NSIS(사용자 단위, 설치 경로 선택, 바로가기), portable, 아이콘, appId, productName, `extraResources`(규칙 DB), 버전.
- 앱 제거 시 사용자 데이터 삭제 여부 확인(NSIS 커스텀 페이지/옵션).
- 프로덕션 빌드에서의 경로(규칙 DB, 헬퍼 실행) 동작 확인, 로그 폴더 확인.
- README: 설치/사용법, SmartScreen 경고 안내(코드 서명 없음), 안전 정책 요약, 알려진 한계.
- 빌드 스크립트 `npm run dist`.

**완료 기준**

- `npm run dist`로 `DiskLens-Setup-x.y.z.exe`와 `DiskLens-Portable-x.y.z.exe` 생성.
- 깨끗한 환경(가능하면 다른 계정/VM)에서 설치 → 스캔 → 설명 표시 → 삭제 제거까지 동작.
- 설치 프로그램 제거 시 정상 삭제, 사용자 데이터 처리 확인.

**지시문**

> ROADMAP 11단계를 진행해줘. 설치 파일과 포터블을 만들고, 설치본에서 규칙 DB 로딩과 관리자 헬퍼가 정상 동작하는지 점검 항목을 정리해서 보고해줘. 점검 중 실제 시스템 파일은 삭제하지 마.
